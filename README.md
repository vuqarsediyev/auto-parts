# Клиентское веб-приложение поиска автозапчастей и аналогов

Клиентское приложение на **React** и **Redux** (без TypeScript) для интеграции с внешним веб-сервисом «Проценка» (Favorit Parts, эндпоинт `http://api.favorit-parts.ru/hs/hsprice/`).

Интерфейс реализует строгий **двухэтапный процесс** подбора автозапчастей и номенклатуры в полном соответствии с предоставленной технической документацией (`wsprice`).

---

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск локального сервера разработки
```bash
npm run dev
```
Приложение откроется по адресу `http://localhost:5173`.

### 3. Запуск автоматических тестов
```bash
npm test
```

### 4. Сборка для продакшена
```bash
npm run build
```

## 📋 Реализация функциональных требований

### Этап 1: Поиск производителей
1. **Поле ввода артикула**: В компоненте `SearchBar` пользователь вводит артикул детали (например, `01089`, `7160500039S`). Также предусмотрены кнопки быстрых примеров из PDF-документации.
2. **Запрос к API**: Выполняется GET-запрос:
   ```
   http://api.favorit-parts.ru/hs/hsprice/?key={key}&number={number}
   ```
   Спецсимволы экранируются согласно требованиям документации.
3. **Отображение списка производителей**: В компоненте `BrandSelector` выводится карточный список найденных брендов (производителей), выпускающих деталь с данным артикулом, с информацией о названии детали и суммарном остатке.

### Этап 2: Получение аналогов и предложений
1. **Выбор производителя**: При клике на конкретного производителя (`Выбрать {Бренд}`) инициируется повторный запрос к API:
   ```
   http://api.favorit-parts.ru/hs/hsprice/?key={key}&number={number}&brand={brand}&analogues=on&info=on
   ```
2. **Итоговая таблица предложений и аналогов**: В компоненте `OffersTable` отображается таблица, содержащая как основную искомую позицию, так и все найденные аналоги.
3. **Обязательные поля для каждой позиции**:
   - **Название / Производитель**: Название детали и бренд (с выделением невозвратных позиций `notRefund`).
   - **Стоимость (цена)**: Согласно документации (*«цену нужно брать из конкретного склада, реквизит в корне остался для совместимости»*), цена рассчитывается на основе актуальных цен складов (`warehouses.price`) с выводом точной цены или диапазона (`от X ₽`).
   - **Доступный остаток на складе**: Выводится суммарный остаток (`count` / сумма по складам), статус наличия и количество доступных складов.
   - **Детализация по складам**: Кнопка «Склады» открывает модальное окно с разбивкой по каждому складу (название, собственный/партнерский склад, остаток, цена склада, дата и время отгрузки, признак невозвратности).

## 🛠 Технический стек и архитектура

- **React 19** (JavaScript / JSX, без TypeScript).
- **Redux Toolkit (`@reduxjs/toolkit`) + React-Redux**:
  - Асинхронные Thunks (`fetchManufacturers`, `fetchOffers`).
  - Централизованное управление состоянием (`stage1`, `stage2`, `filters`, `apiKey`).
- **Стилизация**: **Bootstrap 5** (`bootstrap`) + **Bootstrap Icons** (`bootstrap-icons`) для чистого, адаптивного и современного интерфейса.
- **Обработка состояний и ошибок**:
  - **Компоненты-лоадеры (`Loader`)** с информативными сообщениями о текущем действии.
  - **Компоненты ошибок (`ErrorAlert`)**: обработка сбоев сети, пустых ответов («пустая структура» `brand: ""` из документации), ошибок API (`Empty key!`, `Invalid access key`, `Empty number goods!`, `Request quota exceeded!`) с кнопкой «Повторить».
  - Возможность указания собственного ключа покупателя (`key`) через удобное модальное окно в шапке (по умолчанию используется ключ из документации).
  - Настроен проксирующий маршрут в Vite (`/api/hsprice`) для надежной работы без проблем с CORS и Mixed Content в любых браузерах.
